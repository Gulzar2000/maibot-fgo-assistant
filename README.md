# FGO小助手

基于 [kcn3388/fgogacha](https://github.com/kcn3388/fgogacha) 移植并扩展的 MaiBot 插件，提供 FGO 模拟抽卡、活动与素材查询、真实出率统计、羁绊挖矿计算和账号绑定功能。

本项目仓库：[Gulzar2000/maibot-fgo-assistant](https://github.com/Gulzar2000/maibot-fgo-assistant)。第三方代码和图像来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 安装

声明兼容范围：MaiBot 1.0.0～1.3.19、插件 SDK 2.12.0～2.21.0，Python 3.12 起。上限按本机部署版本填写，后续版本需验证后更新。真实账号绑定、查询及兑换功能目前仅支持 Windows 下的 QQ 账号；支持哔哩安卓、iOS、享游安卓角色。管理员需自行准备协议参数，公开仓库不提供实际参数。

### 1. 安装依赖

```bash
uv pip install -r requirements.txt
```

请安装完整依赖列表；只安装网页解析或绘图库不足以运行账号绑定与安全存储功能。

### 2. 启用插件

通过 WebUI 启用插件并检查配置；手动部署时可参考 `config.example.toml`。运行配置不纳入版本控制：

```toml
[plugin]
enabled = true
```

然后重启 MaiBot 或重载插件。

## 模拟抽卡初始化

以下步骤用于模拟抽卡。活动、素材等公共查询可直接使用；真实账号功能需另行完成协议配置和账号绑定。

### 第一步：初始化数据目录

```
/fgo init
```

创建插件所需的本地数据目录。

### 第二步：获取卡池数据

```
/fgo pools
```

每次调用都会从 [Mooncell wiki](https://fgo.wiki) 下载国服当前及完整未来卡池日程和模拟数据，按开始时间升序排列。文本按每节点最多 1000 字分段，每四个文本节点组成一个带页码的子转发，再将所有子转发嵌套到一张外层合并转发卡片中发送。未来日期标注“预计”，以实际国服公告为准。福袋、Destiny Order、Beast Order 等特殊召唤不使用普通十一连算法。模拟数据获取失败的卡池保留日程并标注不可抽取。

### 第三步：预下载召唤图片（可选）

```
/fgo download
```

从 [Mooncell 英灵图鉴](https://fgo.wiki/w/英灵图鉴) 和 [礼装图鉴](https://fgo.wiki/w/礼装图鉴) 下载自带卡框、职阶及星级的小图，并更新卡片名称索引。图片版抽卡会自动补齐当次结果所需的图片，此指令用于预下载全部素材。执行前会先发送提示消息。

十一连图片按真实截图的 1920×864 布局生成，上排六张、下排五张居中。顶部余额、持有数量、底部奖励与按钮作为固定界面保留；动态替换结果卡片，底部显示“抽卡者 QQ 昵称：卡池名”，超长时省略末尾。新卡片缓存位于 `fgogacha/icons/cards/`，与旧 Atlas 方形头像分开存放。素材缺失、下载失败或损坏会明确报错，不绘制空白占位卡。

## 命令速查

`/fgo 羁绊计算` 或 `/fgo 挖矿`：读取发送者已绑定的国服账号，返回一张羁绊圣晶石报告图，包含当前上限内普通段及梦火段剩余奖励、星级汇总、剩余最多前十名、梦火段距下一级经验，以及与上次查询的逐从者对比。需要先 `/fgo bind`；登录可能使游戏掉线，当天重复抓包沿用现有确认设置，再发同一指令确认。

梦火明确区分“已喂、奖励未获得”和“背包尚未使用”。已解锁总数只包含普通羁绊与已喂梦火待兑现收益；另读背包梦火真实库存，按可投入现有从者的数量估算额外收益，并列出含库存的可挖潜力，不按全员喂满推算。累计奖励按等级推算，不代表余额或领取流水；新获得从者在两次查询之间的收益不推算。同图鉴共享形态去重，已契约但已出售的从者仍保留记录，玛修剧情羁绊不计入。安哥拉曼纽按 6～9 绊每级 2 石计算。公共数据缓存两个自然月，未知图鉴触发一次刷新，刷新失败直接报错。

来源与规则说明见 [羁绊数据说明](res/bond_sources.md)。首次查询建立快照；旧出率历史没有从者羁绊进度，无法据此补出更早对比。

羁绊计算与真实出率抓包的每日取数记录、待确认状态各自独立，执行其中一条不会触发另一条的重复提示；同一账号仍不能同时执行多个登录或兑换操作。

中文别名与原指令等效，均保留 `/fgo` 前缀，参数与原指令相同：

| 原指令 | 中文别名 |
|------|------|
| `/fgo help` | `/fgo 帮助` |
| `/fgo pools` | `/fgo 卡池` |
| `/fgo switch <编号> [子编号]` | `/fgo 切换卡池 <编号> [子编号]` |
| `/fgo stat` | `/fgo 模拟出率` |
| `/fgo stat real` | `/fgo 真实出率`、`/fgo 抓包` |
| `/fgo bind [区服编号]` | `/fgo 绑定 [区服编号]` |
| `/fgo unbind` | `/fgo 解绑` |
| `/fgo tree [兑换数]` | `/fgo 种树 [兑换数]` |
| `/fgo events [关键词]` | `/fgo 活动 [关键词]` |
| `/fgo material <素材>` | `/fgo 素材 <素材>` |

例如：`/fgo 绑定 1`、`/fgo 切换卡池 0 2`、`/fgo 种树 3`、`/fgo 活动 术冠`。中文别名共用原指令的额度、冷却与重复抓包确认。`10`、`100`、`init`、`download` 不增加中文别名。


### 抽卡

| 命令 | 说明 |
|------|------|
| `/fgo 10` | 模拟 11 连抽卡（FGO 十连实为 11 抽），执行时会发送"抽卡中..."提示 |
| `/fgo 100` | 模拟百连，即十次十一连共 110 抽，@ 抽卡者与各稀有度统计在同一条消息中发送，执行时会发送提示 |

单五星从者 UP 卡池启用 330 抽保底：连续 329 抽未获得该 UP 五星从者，第 330 抽必定获得。提前出 UP 或触发保底后重新计数，歪出的五星从者与五星礼装不重置计数。多五星 UP 和无五星 UP 卡池不启用此机制。

保底按实际 QQ 用户分别保存，重启后保留；同一 QQ 在不同聊天中抽取同一池会接续计数。切换到不同卡池或子池时清零，切回旧池也从零开始；重复选择同一个池、卡池列表重新编号不清零。十一连按 11 抽、百连按 110 抽逐抽累计，触发保底后额外发送：`很遗憾，你保底了~`。

正常抽到 UP 五星从者时，额外发送：`恭喜你，你出货了~！`，每次指令最多提示一次。保底获得的 UP 五星不触发恭喜消息；若同一次十一连或百连中既触发保底又正常抽到其他 UP 五星，则分别发送出货和保底提示。

### 素材查询

`/fgo material 羽毛` 或 `/fgo 素材 羽毛` 会发送一张国服素材来源汇总图，无需绑定账号或初始化卡池：

- Free 本 AP 效率前五：按 AP/个排序，显示地点、地图、平均每周回掉落量及样本次数；筛选国服已开放关卡，额外入场消耗单列。
- 当前及未来活动前五：跳过已结束活动，仅显示含该素材的活动，总量拆分商店、任务、点数、首通与固定掉落等；无限池按每池数量单列，不含个人计划或领取进度。
- 未来每日交换券前三期：仅列可兑换该素材的未来月份，显示可选素材、每日及整月上限；不把多选一的选项相加。

整个功能只支持普通铜银金素材、七职阶棋子及技能石，排除传承结晶、QP、圣晶石、圣杯、活动代币等物品。支持中文正式名称、素材 ID 和核实后的玩家别名，如 `羽毛`、`井盖`、`黑灰`、`核桃`、`血瓶`、`术金棋`、`术金饼干`。不支持日文原名，不保留旧版猜测简称和英文职阶拼接；不收录“饼干”“金饼干”“金棋”等跨素材重复的称呼，棋子和技能石别名必须带职阶。普通素材别名维护在 `res/material_aliases.json`，棋子和技能石按中文职阶与金银棋、蓝红金饼干的规则组合。

完整逐项清单及来源见 [素材别名审核表](material_alias_review.md)，含中文正式名称、全部别名和 ID；仅完整匹配，统一空白与全半角。成图左上角显示对应素材图标，图标下载后缓存，文件损坏或下载失败明确报错。

数据来自 [Chaldea 公共数据包](https://github.com/chaldea-center/chaldea-data/tree/main/dist)、效率剧场及 Atlas Academy，国服活动日期匹配 [Mooncell 活动总览](https://fgo.wiki/w/活动总览)，保留预估标记。活动固定收益参照 Chaldea 日服资料，以国服实装为准。交换券按 Chaldea 规则对应到国服月份（2022-09 起为日服年月加 12 个月，之前加 15 个月），不自行编造尚未收录的后续期次。普通 AP 效率未计入减半活动，修炼场仍受曜日限制。

首次查询会一次性获取整套素材数据、国服活动排期及全部支持素材的图标，缓存至插件数据目录 `fgogacha/materials`，无需 `/fgo download`。缓存两个自然月后过期（例如 11 月 9 日至次年 1 月 9 日，月末按目标月份最后一天截取），重启仍可直接读取磁盘缓存，未过期不联网检查更新；到期后的首次查询整体刷新，并按清单哈希复用未变更的数据文件。活动是否已结束仍按查询当天重新判断，不会因为缓存保留而展示过去活动。整批数据和图标成功获取后才写入完成标记；下载、校验、排期解析或绘图异常会明确报错。成功查询只发送一张图片。

### 活动排期

| 命令 | 说明 |
|------|------|
| `/fgo events` | 查询国服当前及页面收录的全部未来活动，按开始日期升序排列 |
| `/fgo events 关键词` | 按名称关键词或别名筛选，例如 `/fgo events 术冠`、`/fgo events 泳装` |

每次查询直接读取 [Mooncell 活动总览](https://fgo.wiki/w/活动总览)，无需先初始化或下载卡池。只显示起止日期（`YYYY-MM-DD`），保留来源的“预估”标记；没有明确结束时间的条目显示“无明确结束日期”。查询覆盖主要活动、纪念活动及总览收录的主线、其他活动，不包含日服及“国服未开放活动”表。已结束活动不在搜索范围内，结束当天仍显示。

短结果直接发送文字，长列表按每节点最多 1000 字、每页最多四个文本节点嵌套合并转发，完整保留所有结果。预估排期以实际国服公告为准；网络或页面结构异常会明确报错。

#### 活动别名配置

内置 22 组默认规则：剑冠、弓冠、枪冠、骑冠、术冠、杀冠、狂冠、EX冠、冠位战、泳装/夏活、万圣、圣诞、情人节、白情、周年庆、元旦、咕哒、巡灵、水怪、阎魔亭、FSF、FSR 等。没有配置 `[events]` 的旧配置会直接使用默认规则，无需手动迁移。

可在插件 `config.toml` 中用下列格式维护规则，完整默认列表见 `config.example.toml`。**显式配置 `alias_rules` 会替换整个默认列表**，如需追加别名，请复制模板中的全部规则后再增改。

```toml
[[events.alias_rules]]
aliases = ["术冠", "术阶冠位战"]
titles = ["冠位戴冠战：Caster"]

[[events.alias_rules]]
aliases = ["泳装", "夏活", "泳装活动"]
titles = ["泳装", "Servant Summer", "迦勒底·U－夏日岛", "迦勒底南海大决战"]
```

名称包含搜索始终保留；查询词完整命中某个 `aliases` 时，额外匹配该规则任意 `titles` 名称片段，合并结果不重复。查询忽略空格、英文大小写和全半角差异（包括冒号）。例如“术冠”同时匹配 Caster 冠位战及其前夕、应援活动，不匹配 Archer 冠位战；“万圣节”也会匹配“南瓜农场屠杀”。别名不会扩展为其他别名，也不匹配查询词的一部分。

列表和单项不允许空白字符串。要关闭全部别名扩展、只保留名称搜索，可配置：

```toml
[events]
alias_rules = []
```

修改后重载插件或重启 MaiBot。类别别名按明确的活动名称片段维护，未来出现名称完全不同的新泳装等活动时，需要补充对应 `titles`。

| `/fgo pools` | 自动下载国服当前与未来卡池，按时间升序分段合并转发 |

### 帮助与个人统计

| 命令 | 说明 |
|------|------|
| `/fgo help` 或 `/fgo` | 简述全部指令格式和效果 |
| `/fgo stat` | 仅查看模拟出率 |
| `/fgo stat real` | 查询已绑定账号的真实出率，未绑定时提示使用 `/fgo bind` |

模拟五星出率 = 五星从者总数 / 实际总抽数，包含 UP、非 UP 和保底获得的五星从者，五星礼装不计入。每位 QQ 独立累计，切换卡池、跨日和重启均保留；查询不消耗每日额度，也不受抽卡冷却限制。旧版没有保存累计五星数量，无法补算历史出率，统计从本次更新后的抽卡开始；无记录时提示先抽卡。

例如：`你的模拟抽卡五星出率为1.48%（49 ★5/3300 抽），评级为 Grand 欧皇`。

评级阈值与 [Chaldea 的 GachaLuckyGrade.fromRate](https://github.com/chaldea-center/chaldea/blob/main/lib/app/modules/import_data/sniff_details/report/report_data.dart) 及[中文评级名称](https://github.com/chaldea-center/chaldea/blob/main/lib/l10n/intl_zh.arb)一致，按未四舍五入的实际出率判定：

| 实际出率 | 评级 |
|----------|------|
| ≥ 1.25% | Grand 欧皇 |
| ≥ 1.15% 且 < 1.25% | 欧皇 |
| ≥ 1.05% 且 < 1.15% | 中庸 |
| ≥ 1.00% 且 < 1.05% | 略非 |
| ≥ 0.85% 且 < 1.00% | 非酋 |
| < 0.85% | 酋长 |

展示样式与跟随策略只能在本地配置中修改，已移除对应聊天指令。全部聊天指令统一使用 `/fgo 子命令`，旧的连写格式不再生效。

## 抽卡结果展示

抽卡结果支持两种展示方式：

- **文字版**（本地配置 `display_mode = "text"`）：纯文本，显示每抽的星级、类型、卡片编号与名称
- **图片版**（本地配置 `display_mode = "image"`）：仿游戏界面，带背景和边框的图形化展示，缺少卡图时自动下载，也可用 `/fgo download` 预下载

## 配置说明

`config.toml` 中的可配置项：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `[gacha].display_mode` | `"image"` | 默认展示样式，可选 `"image"` 或 `"text"` |
| `[gacha].follow_pool_type` | `"latest"` | 自动跟随策略，可选 `"latest"` 或 `"story"` |
| `[gacha].daily_limit` | `100` | 每位 QQ 每日实际抽卡次数上限 |
| `[gacha].cooldown_seconds` | `15` | 每位 QQ 独立的抽卡冷却时间（秒），0 表示关闭 |
| `[gacha].auto_update_hours` | `0` | 自动更新卡池间隔（小时），设为 0 禁用 |

配置模板见 `config.example.toml`。`daily_limit` 按每位 QQ 的实际抽卡次数计算，十一连消耗 11 次、百连消耗 110 次，同一 QQ 在不同群聊和私聊共享自己的每日额度与冷却。剩余额度不足以完成整次抽卡时不抽取、不扣次数。使用默认上限 100 时每日最多进行九次十一连；要使用百连，上限需至少为 110，也可配置为 10000 等更大数值。

当天用量与冷却时间保存在用户抽卡状态中，切池和重启不会清零；每日额度在北京时间零点重置，保底进度不随日期重置。达到上限时回复 `已达到每日抽卡上限（x次），别太贪心哦~`，冷却未结束时回复 `抽卡还在冷却中，太频繁啦！`；同时满足两种限制时优先提示上限。

## 常见问题

**Q: 获取卡池失败？**
A: 检查网络是否能访问 https://fgo.wiki 。如 wiki 页面结构有变动导致抓取失败，请反馈给开发者。

**Q: 图片版不显示/显示异常？**
A: 检查是否能访问 `fgo.wiki` 和 `media.fgo.wiki`；也可执行 `/fgo download` 预下载召唤图片。日志会列出具体失败的卡片编号。确认 `res/summon_background.png` 完整存在。

**Q: 字体显示为方块？**
A: Windows 使用系统微软雅黑或黑体；其他系统请置入 `res/SourceHanSansSC-Regular.otf` 字体文件。缺少中文字体时明确报错。

**Q: 抽不出货？**
A: 这是假的，别当真。

## 数据来源

卡池数据来自 [Mooncell - 玩家共同构筑的FGO中文Wiki](https://fgo.wiki)，按召唤活动页的 UP 编号、逐张概率及对应时期常驻名单构建概率。仅供娱乐，结果无参考价值。

## 数据与概率校验

- 刷新列表后按原页面链接与子池编号保留会话的卡池选择；已不在列表或无法抽取的池改为首个有效池。
- 每个子池独立解析，`/fgo pools` 展示可用于 `/fgo switch 卡池编号 子池编号` 的实际子池编号。
- 普通抽取按每张 UP 概率构建组权重，例如单 UP 五星从者 0.8%，其余五星从者合计 0.2%；十一连按九次普通抽取、一次金卡保底、一次从者保底抽取后打乱顺序。
- 卡池有非法编号、重复卡片或非法权重时明确报错，不生成空编号或占位卡。更新仅保存校验通过的卡池，失败详情写入日志。
- 卡片名称索引合并 Atlas 日服与国服，名称优先使用国服数据；召唤图片从 Mooncell 图鉴嵌入数据读取实际地址。每次 `/fgo download` 刷新索引，已有图片校验通过后复用，损坏图片重新下载。
- 修复前的卡池缓存不兼容，请重新运行 `/fgo pools`；图片资源使用 `/fgo download` 补齐。

- 卡池不再依赖 Wiki 模拟器页面是否存在，推荐召唤活动页中的每组名单独立构建为子池。
- 常驻名单按原始日服日期分时调整，包含蛇女房加入及礼装轮换；英灵星行、英灵极点按官方限定排出名单构建。

## 账号绑定与真实出率

- `/fgo bind`：仅显示区服选择提示，不生成二维码。
- `/fgo bind 1`：哔哩安卓；`/fgo bind 2`：iOS；`/fgo bind 3`：享游安卓。必须明确指定区服，不再接受英文区服参数。
- 群聊、私聊均可扫码绑定；群聊将 @ 命令发送者、提示和二维码放在同一条消息中，私聊不加 @。每个 QQ 保存一个账号和区服，重新绑定成功后替换原绑定，失败保留原绑定。
- `/fgo unbind`：取消该 QQ 正在进行的账号操作、删除本地登录凭据，保留模拟抽卡记录；群聊和私聊都可解除自己的绑定。
- `/fgo stat`：仅显示模拟出率，不读取绑定、不调用游戏接口，也不受扫码或真实查询任务影响。
- `/fgo stat real`：显示本次抓包的账号名字、好友码及真实出率，未绑定时提示 `/fgo bind`。已绑定时实时登录取数，可能使正在运行的游戏掉线。

二维码等待和游戏取数在后台执行，网络请求、二维码绘制和文件读写在线程执行；同一 QQ 同时只允许一个账号操作。重载插件会取消尚未完成的操作。

凭据按 QQ 存放于 SDK 数据目录 `fgogacha/bindings/<QQ>.dpapi`，使用 Windows DPAPI CurrentUser 加密，只能由同一 Windows 用户解密。二维码不落盘且发送时关闭聊天内容入库；不保存原始 toplogin，不在消息或日志中输出凭据。解绑删除本地副本，不撤销官方服务端已发放的授权。

管理员需自行在插件 `private/` 下提供 `game-protocol.json` 和 `game-protocol-uo.json`（应用协议参数，来自自行维护的 Capture Kit）；公开仓库不包含这些参数、账号凭据、绑定密钥或真实抓包结果。此目录被独立仓库忽略。部署到其他系统前需重新实现对应的安全凭据存储，当前真实账号功能仅支持 Windows；未配置协议参数时仍可使用模拟抽卡与公共数据查询。

统计参考 FGO-Capture-Kit 的 `GachaStatistics.psm1`：累加 `userGacha.num`，排除友情池；按 `userSvtCollection.totalGetNum` 累加可抽取五星（包括重复及已出售从者），分子分母各扣每个福袋的一次保底。自选及福袋额外五星未自动扣除。未知卡池标记“暂估”，未知已获得图鉴 ID 不计算真实出率。离线分类索引为 `res/gacha_metadata_cn.json`，保留原来源和哈希，可运行 `tools/update_gacha_metadata.ps1` 更新。索引合并国服与日服的从者、礼装 ID，并以日服从者覆盖国服未来实装；礼装明确标记为不参与五星统计。遇到未知已获得图鉴时，诊断日志会记录具体 ID。

登录协议模块来源和 MIT 许可证见 `gacha/account_protocol/UPSTREAM.md`、`LICENSE`。当前沿用参考工具的游戏协议版本，游戏更新导致不兼容时需同步维护协议参数。

## 本地扫码工具与管理员导入

推荐通过 `releases/FGO账号绑定工具-便携版.exe` 在用户本机输入 QQ 号、选择区服并扫码。此流程不向 QQ 发送二维码。用户将生成的 `<QQ号>.fgobind` 私发给管理员，管理员核对发送者后，原名放入插件的 `bind-import/` 目录。该 QQ 下次 `/fgo stat real` 时自动导入，无需重启；`/fgo bind` 同时支持群聊和私聊扫码。

文件采用 RSA-OAEP(SHA256) 包装随机 AES-256-GCM 密钥，仅对应机器人能解密；导入后仍使用原 DPAPI 凭据库。成功的文件改为 `.imported`，不重复读取。解绑同时清理 DPAPI 凭据及此 QQ 的待导入、已导入文件。

管理员自行生成导入密钥，公开仓库不包含本机的公钥或私钥。可在插件目录运行 `uv run python -c "from pathlib import Path; from gacha.binding_transfer import prepare_key; prepare_key(Path('private/import-private.dpapi'), Path('tools/import-public.pem'))"`。构建的工具只包含 `tools/import-public.pem`；私钥 `private/import-private.dpapi` 不进入分发包。需要保留该私钥，并由同一 Windows 用户运行插件。后续生成会复用私钥，不能将私钥发给使用者。QQ 号由使用者填写，加密文件不证明 QQ 归属，需要管理员人工核对。

构建入口：`tools/build_binding_tool.ps1 -PythonRoot <Python3.13便携目录>`，需自行准备 Python 3.13 便携运行环境及本机协议配置。运行源码后端需要 qrcode、Pillow、pycryptodome；构建时打包进 EXE，不属于插件运行依赖。依赖许可证保留在内置运行环境。构建产物及本机密钥不纳入 Git；工具及导入测试使用合成凭据，真实扫码和实际 QQ 文件传输仍需人工验证。

便携版在 EXE 同目录的 `.fgo-runtime/` 解包运行文件，不依赖 AppData 写入权限。请放在下载目录等自己可写的位置，以普通用户运行。

### 每日重复抓包确认

同一 FGO 账号（按登录账号和区服识别）当天成功取得 toplogin 后，再次 `/fgo stat real` 会先回复“你今天已经抓包过一次了，确定还要再抓包吗？”，不调用游戏接口。同一人再次发送命令后才进行本次抓包；后续重复抓包仍需再次确认。首次登录失败不计次数，成功取数但统计格式出错仍计入。

日期按北京时间计算，成功记录保存在 SDK 数据目录的 `fgogacha/capture_history.json`，追加保留每次可计算的出率快照，重启后保留。确认状态只在内存中保存且仅当天有效。同账号绑定到不同 QQ 共享成功记录，各发送者分别确认；解绑只清除登录凭据、待导入及已导入绑定文件，保留当天成功日期、真实出率摘要与全部快照。扫码绑定时成功验证角色取得的 toplogin 同样计入记录。所有新抓包与离线导入记录均按 FGO 游戏 ID 单独保存；同 QQ 换绑不同游戏账号时分别归档，同一角色换绑到其他 QQ 时续接原曲线。已确认 FGO ID 的旧摘要自动转存到对应账号；缺少 FGO ID 的旧摘要保留原位，后续通过原登录账号抓包确认角色后归档。

真实出率回复包含昵称、好友码、当前 AP、出率与评级四行文字，随后附累计抽数—出率曲线图。未知卡池时在评级后标注“（暂估）”。图内角色吐槽由固定句库按统计情况选择，不调用模型。`[real_statistics]` 只保留 `confirm_repeat_capture`，旧版六档评级附加文案配置已移除。
